# Mermaid Syntax Parsing, Sanitization & Client Validation

> **Overview:** Procedural instructions for the Agentic Dev to prompt for, sanitize, parse, and validate Mermaid.js diagram syntax generated by LLMs before storing or rendering on the frontend.  
> **When to Use:** Consult when integrating Mermaid diagram generation within the AI synthesis pipeline, building the diagram rendering component, or implementing syntax fallback guards.

---

## 1. Generation & Prompting Directives
- **Allowed Diagram Types:** Explicitly restrict the model to simple, robust diagram topologies: top-down flowcharts (`graph TD` or `flowchart TD`) and sequence diagrams (`sequenceDiagram`). Forbid complex or experimental Mermaid diagram types prone to syntax errors.
- **Node Label Formatting:**
  - Instruct the LLM to wrap all node labels in double quotes inside brackets (e.g., `A["Client Request"] --> B["API Gateway"]`).
  - Forbid unescaped special characters (parentheses, braces, brackets, quotes, slashes, hyphens) inside unquoted node identifiers or labels.
- **Theme Constraints:** Direct the model to generate plain structural topology without inline style attributes, colors, or CSS classes, delegating visual theming entirely to the frontend renderer.

---

## 2. Server-Side AST & Regex Sanitization
- **Fence & Wrapper Stripping:**
  - Extract the raw diagram code from any enclosing markdown fences (```mermaid ... ```) or whitespace padding prior to validation.
- **Syntax Normalization:**
  - Verify that the diagram text begins with a valid declaration header (`graph`, `flowchart`, `sequenceDiagram`, `classDiagram`, `stateDiagram-v2`).
  - Scan for unescaped reserved symbols within node declarations and escape or strip them deterministically.
  - Detect and remove duplicate node identifiers or self-referential syntax dead-ends that break the rendering graph.

---

## 3. Client-Side Validation & Safe SVG Rendering
- **Pre-Render Syntax Verification:**
  - Before injecting diagram source into the DOM, invoke Mermaid's syntax parser (`mermaid.parse`) inside an asynchronous try-catch block to verify structural validity.
  - Initialize the Mermaid engine with strict dark-palette defaults matching the zinc design tokens (`zinc-800` node fills, high-contrast borders, clean monospace font family).
- **Graceful Error Fallback (No Red Error Boxes):**
  - If `mermaid.parse` fails or throws an exception, catch the error immediately and prevent the default Mermaid error UI from replacing the container.
  - Render a clean, subtle fallback block (e.g., a "Diagram unavailable for this log" placeholder with an option to toggle raw text view) so a broken syntax string never crashes the layout or degrades user experience.
- **Isolation & Zoom Integration:**
  - Render successful SVG outputs inside a dedicated container with horizontal scroll handling (`overflow-x-auto`) on mobile and an optional expand-to-lightbox action for complex system flows.

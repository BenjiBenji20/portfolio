# Sanity Content Lake: GROQ Projections, Mutations & Cache Revalidation

> **Overview:** Procedural instructions for the Agentic Dev to query, mutate, and sync Sanity CMS data. Establishes priority-based sorting hierarchies, real-time on-demand revalidation flows, idempotent mutations, and typed GROQ projections.  
> **When to Use:** Consult when authoring Sanity client instances, writing GROQ queries, structuring schemas with prioritization, executing serverless writes, or building the Next.js revalidation webhook.

---

## 1. Schema Prioritization & Ordering Directives
- **Explicit `priority` Field Standard:**
  - Add an optional integer `priority` field to schemas that require manual visual prominence (e.g., `project`, `techStack`, `featuredLog`).
  - Set schema validation to enforce integer values with sensible step increments (e.g., 10, 20, 50, 100) to leave room for intermediate sorting.
- **Descending Order Sorting Rules:**
  - When fetching lists, always order by priority descending first, with secondary fallback attributes to guarantee deterministic sorting:
    - Projects/Collections: `order(coalesce(priority, 0) desc, _createdAt desc)`
    - Tech Stack pills: `order(coalesce(priority, 0) desc, name asc)`
  - Use `coalesce(priority, 0)` inside GROQ expressions so documents lacking an explicit priority number default to `0` and gracefully appear beneath prioritized items rather than breaking sort logic.

---

## 2. Real-Time Sync, CDN Strategy & On-Demand Revalidation
- **Direct Edge Ingestion (`useCdn: false`):**
  - Configure server-side Sanity client instances handling mutations and on-demand cache regeneration with `useCdn: false`.
  - Bypassing Sanity's API CDN prevents edge propagation lag, ensuring freshly written or modified documents are immediately readable by serverless handlers.
- **Next.js On-Demand Tag Revalidation (`/api/revalidate`):**
  - Create a dedicated revalidation route handler triggered by a Sanity GROQ-powered webhook whenever documents are created, updated, or deleted.
  - Verify incoming webhook signatures using the shared Sanity webhook secret (`@sanity/webhook`) before proceeding.
  - Extract the mutated document's `_type` and `slug.current`.
  - Trigger fine-grained cache purging using `revalidateTag(...)` matching the document type (e.g., `projects`, `devlogs`, `tech-stack`) and path-specific routes (`revalidatePath(...)`) so Next.js regenerates the static HTML immediately without waiting for time-based TTL expirations.

---

## 3. Parameterized & Injection-Safe GROQ Directives
- **Zero Raw String Concatenation:**
  - Never interpolate variables directly into GROQ query strings (`groq\`*[_type == "${type}"]\`` is strictly forbidden).
  - Always pass runtime values via parameterized query objects:
    - Query: `*[_type == "project" && slug.current == $slug][0] { ... }`
    - Params: `{ slug }`
- **Projection Minimization (No Blind `*` Projections):**
  - Fetch strictly the fields needed by the consuming view.
  - Standardize project projections: `_id`, `title`, `slug`, `coalesce(priority, 0)`, `summary`, `coverImage`, `techStack[]->{ name, icon }`.
  - Standardize devlog projections: `_id`, `title`, `slug`, `commitSha`, `category`, `publishedAt`, `summary`, `affectedModules`.

---

## 4. Idempotent Mutations & Patch Integrity
- **Predictable Document Identifiers:**
  - For automated devlogs generated by GitHub webhooks, compute deterministic document IDs based on the commit hash (e.g., `devlog-${commitSha}`).
  - Use `client.createIfNotExists(...)` rather than `client.create(...)` to guarantee that duplicate webhook deliveries never create duplicate CMS records.
- **Atomic Transactional Patches:**
  - When updating existing records, use transactional mutations (`client.patch(id).set(...).commit()`).
  - Ensure nested structures (such as arrays of tags or changelog references) use atomic operations (`setIfMissing`, `insert`) rather than overwriting entire root objects.

---

## 5. Asset Uploads & Portable Text Block Assembly
- **Direct Stream Asset Pipeline:**
  - When ingesting remote images or screenshots from GitHub diffs, fetch the remote resource as a byte buffer and stream it directly to Sanity's Asset API (`client.assets.upload('image', buffer, { filename })`).
  - Store the resulting asset reference (`_type: 'reference', _ref: asset._id`) within the target document patch.
- **Structured Portable Text Generation:**
  - When transforming raw markdown or AI narrative into rich text fields, convert the payload into valid Sanity Block format (`_type: 'block'`, `children: [{ _type: 'span', text: '...' }]`) rather than dumping raw markdown strings into untyped text fields.
